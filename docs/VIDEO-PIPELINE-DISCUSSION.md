# 视频重做翻车根因复盘与探讨

> 适用范围：织戏台（Android 端视觉小说工作站，包名 com.zhixitai.vn）四期教学视频重做。
> 本文只做复盘与施工规范：不改任何脚本、不动 APK 源码、不重打包、不占用真机。
> 证据口径：下文引用的时长、时间码、版本号、坐标均为已复核结论，未重新测量；佐证路径见各条。

## 〇、新口径（重做必须遵守，不可改动）

- 四期固定主题：① 工作台与两栏收起；② 八步引导；③ 不会就问 / 自填 API；④ 端上打包。
- 每期 45–120 秒；画面 1920×1080、16:9。
- 画面严禁出现手机状态栏；画面只标 `github.com/SukaKanger`；爱发电只进文案与置顶评论，不进画面。
- 素材必须来自真机 1.1.7-beta.39 截图。
- 只教软件用法：装包、Termux、离线包释放、权限授予，口播与画面一个字都不许出现。

## 一、结论先行

旧五期成片在素材版本、时间码算法、时长节奏、版面裁切和验收口径上同时失守，还混入了本次口径明令禁止的内容，没有一条可直接沿用，必须整批作废、按新四期口径重做。

## 三、对「只保留设计和思路」的解读

判据原则：保留的是排版参数、信息层级、结构节奏与配色方案；旧的位图、文案、时间码、音轨一律不继承。能否复用一条旧产物，只看它是否与 beta.39 素材和新四期口径绑定——绑定旧内容的全部重制。

### 3.1 该继承的资产

| 资产 | 继承内容 | 可执行判据 |
| --- | --- | --- |
| 左下字幕条 | 字幕位于画面下部、字号与半透明底条的视觉方案 | 只继承位置、字号、底色透明度等排版参数；旧 SRT 的文本与时间码不继承，按新文案重写 |
| 片头卡信息层级 | 品牌行 → 产品名 → 主张句 → 期号标题 → 仓库地址的五层顺序 | 层级顺序保留；卡面文字按新四期主题重写，旧卡面位图不直接复用 |
| 四段式节奏 | 开场固定句 → 界面总览 → 分步操作 → 收尾仓库地址 | 结构保留；每段镜头数与时长按新口播重排，不沿用旧分镜 |
| 卡片视觉 | 深色底 `0x0b0b0d`、琥珀色描边线、白 / 灰文字配色 | 色板与线条参数保留；旧卡片位图作废，按新模板重绘 |

### 3.2 必须扔掉的产物

| 类别 | 具体对象 | 丢弃判据 |
| --- | --- | --- |
| 旧截图 | `build\*.png`、`build\video\v2\` 下 beta.2601 / beta.29 等非 beta.39 图片 | 截图内版本号读数不是 `1.1.7-beta.39`，一律弃用，不得挑一张「差不多的」顶替 |

## 四、新口径下的剩余风险与反例推演

1. **真机被多个子代理并发抢用，截图串状态。** 多个代理连同一台设备，前一个代理的页面状态没退干净，后一个截到的是串状态画面。反例：截「问」面板时，上一个代理还停在打包台。缓解：截图前先 dump 当前页面标题 / 页签，与目标页一致再截；本期不占用真机做与素材采集无关的操作。
2. **状态栏裁切高度按固定值写死，不同方向裁切结果不一样。** 竖屏与横屏状态栏高度不同，一刀切容易裁不干净或多裁 UI。反例：横屏帧顶部仍露出 Wi‑Fi 图标。缓解：每张素材进片前逐帧检查顶部区域，而不是只依赖一个固定裁切像素值。
3. **beta.39 素材覆盖不到「问」「引导」两页。** 这两类页面在 beta.39 上的入口或浮层形态若与旧截图不同，会出现无图可用、拿旧图凑数。反例：第 3 期只能用旧版整页问答截图。缓解：写文案前先在 beta.39 真机上把四个主题涉及的页面逐个走到，列出截图清单；缺页先补采，再排镜头。
4. **45–120 秒与四个主题的信息量不匹配。** 「八步引导」「端上打包」步骤多，时限内讲不完；硬压会一句塞三四个动作，硬拖又回到旧片一句 5–8 秒的毛病。反例：第 2 期八步每步只给 3 秒，画面还没看清就切走。缓解：先按口播字数估时长（一句话约一秒），超 120 秒就拆步骤或删动作，不靠拉语速凑时长。
5. **旧模板残留资助信息。** 片头卡 / 尾卡复用旧工程文件时，旧模板里带过的入口可能被一起带进新画面。反例：尾卡除 `github.com/SukaKanger` 外还出现其他赞助地址。缓解：新卡面逐字核对，画面允许出现的外链只有 `github.com/SukaKanger`；资助信息只写进文案与置顶评论。
6. **口播压到节奏后，一句话仍然过长。** 按「一句话一秒」压缩后，某句仍超过 5 秒，配音与字幕被迫拉长。反例：一句 40 字的操作说明占 8 秒，画面停在同一帧。缓解：写稿时单句不超过约 15 字；超长句拆成两句、两个镜头。
7. **时间码重算后未做单调性校验。** 即便换掉取整方式，新 SRT 仍可能出现起始大于结束、分钟不进位。反例：新片字幕再次出现 `start > end`。缓解：出片前校验每条 `end > start`，且下一条 `start` 不小于上一条 `start`。
8. **截图版本号未留痕，旧 UI 混入成片无法追溯。** 采集时没记录每张图对应的版本，后期分不清哪张是旧界面。反例：成片某帧页签还是旧的「工作台 / 终端 / 环境 / 关于」。缓解：素材文件名带 beta.39 标记，成片前抽帧核对版本读数。
9. **打点坐标点空，演示步骤失真。** 自动化采集凭截图目测坐标，偏高 50–60px 点空；离屏节点 `bounds=[0,0][0,0]` 会点到 (0,0)（见 `docs\BUG-ENV-CLICK.md`）。反例：镜头里按钮没被点中，旁白却说「点这里」。缓解：采集一律取 `uiautomator dump` 的 `bounds` 中心点；零尺寸节点跳过，先滚到可见再取。
10. **配音时长漂移，拼片话赶话或留空。** 同一段文本两次生成时长不一致（见 `docs\PITFALLS.md` #54）。反例：音轨比画面短 3 秒，片尾空放；或比画面长，尾句被切掉。缓解：配音按目标时长传 `duration`，成片前核对音轨总时长落在 45–120 秒区间。
