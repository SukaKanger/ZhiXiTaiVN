# 环境页「点了没反应」诊断记录

日期：2026-11-14　版本：1.1.7-beta.39（com.zhixitai.vn，vivo V2219A / API 33）

## 结论先说

**不是应用的点击层坏了。** 是自动化打点打歪了：凭截图目测的 y 坐标普遍偏高 50–60 px，落在按钮上方的标题/留白里，所以既没 toast 也没状态变化。改用 `uiautomator dump` 的 `bounds` 取中心点后，同一颗按钮一次命中。

证据（11:20 复测）：

- 目测点 `释放离线工具包` 于 (300,267) → 无反应（该点是按钮上方文字区）
- dump 得 `bounds=[159,327][462,438]`，点中心 (310,382) → 立刻弹 toast「离线包已释放，复制命令到 Termux 跑一次。」
- 释放结果复核：`/sdcard/Download/WebGALStation/offline` 267 MB、顶层 5 项、`debs/` 51 个

## 那么之前「装本机 Termux」到底怎么回事

同一条错因：截图里按钮可见位置估成 (1290,778)，真实中心比这低几十像素。按钮没坏，是手指没落在它身上。

顺带发现另一个真问题：`uiautomator dump` 对**离屏**节点返回 `bounds=[0,0][0,0]`，脚本若直接取中心就会点到屏幕左上角 (0,0)——本轮就发生过一次 `tap 0,0`。**规则：bounds 宽高为 0 的节点一律跳过，先滚动到可见再取。**

## 仍然成立的改进项（非 bug，但该做）

1. 环境页 ② 行「装本机 Termux」在 Termux 已装时隐藏（`renderEnv()` 里 `hidden = !!env.termux`），逻辑正确；但它依赖页面滚动才能看见，新机首启容易找不到。首启 gate 已提供入口，可接受。
2. 首启 gate 在「装完/跑完了吗」后会再次弹出——设计如此（未跑自检就不放行），但连续弹会烦。可加「本次跳过」。
3. `#btnTermuxInstall` 的资产回退走后台线程抽 108 MB，抽取期间按钮无 loading 态，用户会以为没反应。**建议加禁用 + 「正在解包 108 MB…」文案**，这是真实可感的「点了没反应」。

## 回归清单

- [ ] Termux 已装时按钮隐藏
