## 三条明确没修的，以及为什么

1. **5.3 预览 iframe 能调管理桥**：`addJavascriptInterface` 是整页注入，换端口、换 origin 都隔不断；要真隔离得把预览扔进第二个 WebView（不带桥）或独立进程。这是一次结构性改动，硬塞进这批会把刚验过的预览链路搞成半坏。
2. **1.1 拆上帝类**：纯搬移，收益在以后；现在拆等于在刚改过 40 处错误路径的文件上再来一次大手术。
3. **9.1 单测**：没有测试框架，新增一套 JVM 测试基建的工程量比它保护的东西还大。

三条都写在这里，不算「忘了」。

## 真机追加修正（beta.22 / beta.23）

跑端上构建时又抓到两条，都不在原评审清单里，但属于「版本必须真迭代」这一条红线：

- **游戏包 versionName 停在 1.1.5**：前端 `fVersionName` 兜底写死 `'1.1.5'`，Java 的重命名开关是 `if (versionCode > 2601)`，第一个包正好 2601 不触发。前端兜底改 `1.1.6`；Java 去掉 code 开关，名字一律以 `V.BASE` 为准并校验 `startsWith(V.BASE)`，对不上就覆盖。重测端上产物 `2604 / 1.1.6-beta.4`。
- **端上产物标题菜单是德语**：WebGAL 4.6.4 只认 `localStorage.lang` 的数字枚举，缺键时落 `de`。在 `src/assets/engine/index.html` 里补一段「键缺失才写 0」的引导脚本，重测中文菜单正常。这是对上游引擎唯一的改动，按 MPL-2.0 在 README 第九节明示。

变量名坑：新加的 `String base` 与同方法后面的 `File base` 撞名，`javac` 直接报错，改名 `verBase` 才过。两条都已写进 `docs/PITFALLS.md`（#46 / #47）。
